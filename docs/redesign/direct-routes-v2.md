# «Мимо Шлюпки», вторая версия: замечания после 0.2.6-test5 (27.11.2026)

Первая версия: вкладка «Мимо Шлюпки» (model/direct_routes.dart, widget/tunnel_direct_view.dart).
Windows ведёт маршрут по адресу, а не по программе: адрес из списка идёт мимо Шлюпки у всех программ.
Отсюда общее правило для всех новых точек входа: добавлять можно только то, что уже идёт напрямую
(«Мимо VPN» или «Авто» с прямым путём). Иначе пункт серый: «Сначала выберите «Мимо VPN»».

Уже сделано: имена серверов в подписке (N, F, РФ → N, РФ → F, РФ → туннель → N, РФ → туннель → F).

## Этап 1. Общий диалог и модель

- Один диалог для всех точек входа: «Добавить» (действует с подключения VPN) и
  «Добавить и применить сейчас» (только при включённом VPN, с текущим предупреждением о разрыве).
- Записи хранят, откуда взялись: приложение, сайт (`discord.gg`) или «добавлено вами».
- Не больше 64 адресов за одно добавление: каждый адрес даёт Windows около 30 маршрутов.
- Только публичные IPv4; IPv6 и домашние адреса пропускаются молча, в числе (n) не считаются.

## Этап 2. Точки входа

- Меню пути приложения и группы («Сейчас в сети», «Все правила»): под чертой действие
  «Мимо Шлюпки: N адресов сейчас». Берёт UDP-адреса текущих соединений (без TCP и UDP 443:
  это сайты и CDN). В «Все правилах» — только пока приложение в сети. Уже в списке — «✓» и переход
  к группе на вкладке.
- Меню соединения:
  - «Только IP x.x.x.x» → «Мимо Шлюпки»: один адрес.
  - «Сайт X и поддомены» → «Мимо Шлюпки»: сразу адреса текущих соединений с этим сайтом, дальше
    дозапоминание раз в 10 с (как адреса игр), забывание через 30 дней. Подменных адресов в ядре нет,
    имя берётся из соединения (sniff), поэтому это работает. Адрес, на который ходят и другие сайты,
    не берём и пишем «общий с другими сайтами» (CDN: на нём бывают заблокированные сайты).
  - «Сайт — в группу»: без изменений.
- «Ошибки»: значок «мимо Шлюпки» рядом с IP в каждой строке; рядом с «Скопировать IP (n)» кнопка
  «IP (n) мимо Шлюпки», n — уникальные публичные IPv4 этого сайта или программы.

## Этап 3. Вкладка «Мимо Шлюпки»

- Убрать кнопку «Никогда мимо…» (запрет остаётся в меню адреса).
- Пункты меню адреса: «Убрать» (игра может запомнить снова) и «Убрать и больше не добавлять».
- Группировка по приложениям и сайтам, как в «Сейчас в сети»; «Добавлено вами»; сети Blizzard и Steam.
- Две колонки: «Мимо Шлюпки» и «Только через Шлюпку» (бывшее «Никогда мимо»); в узком окне друг под другом.
- В «Только через Шлюпку» вместо «Разрешить» два пункта: «Вернуть в «Мимо Шлюпки»» и «Удалить из списка».

## Этап 4. Меню пути

- «Авто», «Мимо VPN», «Через VPN ▸». В подменю: «Любой — выберет Шлюпка» и серверы.

## Этап 5. Сети Steam

- Список сетей Valve (AS32590) по образцу Blizzard, переключатель «Сети Steam». Действует, когда
  Steam или его игра в «Мимо VPN». Помогает только играм Valve (CS2, Dota 2); адресов игровых
  серверов Steam в журналах нет, только магазин и CDN — их не брать.

## Этап 6. «Сейчас в сети»

- Метка у приложения «часть трафика мимо Шлюпки — здесь не видна»; по нажатию — его группа на вкладке.

## Этап 7. Перенос привязок при смене имён серверов

- Правила и выбранный сервер привязаны к имени. При обновлении подписки сопоставлять старый и новый
  сервер по адресу и порту и переносить привязку.

## Приёмы (как сделал бы опытный программист)

| Задача | Приём |
|---|---|
| Модель списка | Чистые функции без виджетов и файлов (`direct_routes.dart`): легко проверить тестами. Неизменяемые объекты, `copyWith`, тот же объект при «ничего не поменялось» — без лишних перерисовок и записей на диск |
| Совместимость файла | Версия схемы в JSON, чтение старой (`blizzard: bool` → `nets: {blizzard, steam}`), запись только новой. Тест: старый файл читается |
| Отбор адресов | Одна функция `directCandidates(items, connections)` для всех точек входа: публичный IPv4, путь напрямую, без конфликта (тот же адрес не виден через VPN и у чужого сайта), не больше 64. Один источник правды — одно место для ошибок |
| Сайт и поддомены | Как кэш ARP: «знаем адреса, пока видим их», запоминание в фоне раз в 10 с и забывание через 30 дней. Подменных адресов в ядре нет — проверено |
| Наборы сетей (Blizzard, Steam) | Таблица данных вместо кода под каждую компанию: `KnownNets(id, название, программы, сети)`. Сети — из открытых данных маршрутизации (RIPEstat, AS32590), с датой |
| Общий диалог | Одна функция показа, два исхода. Применение — уже проверенный путь «сначала добавить, потом убрать» |
| Меню пути | Вложенное меню `SubmenuButton`; список пунктов строится одной функцией для всех экранов, поэтому правится в одном месте |
| Перенос привязок | Сопоставление по устойчивому ключу (адрес:порт сервера), а не по имени; переносим, только если совпадение ровно одно, иначе не трогаем |
| Проверка | Сначала тест на модель (красный → зелёный), потом виджет-тест на точку входа; снимок экрана после каждого видимого шага; отдельный коммит на шаг |

## Оценка и новый порядок

Что могло пойти не так в исходном порядке:
- Этап 2 (точки входа) правит то же меню, что этап 4 (подменю «Через VPN»): дважды правка одного кода
  и тестов. → Сначала меню, потом точки входа.
- Группировка вкладки (этап 3) зависит от того, откуда адрес (этап 1). → Модель раньше вкладки.
- Steam (этап 5) — это тот же механизм, что Blizzard. Если обобщать после вкладки, вкладку придётся
  переделывать. → Обобщить наборы сетей вместе с моделью.
- Меню на «Все правила» открывается, когда «Сейчас в сети» не опрашивает ядро. → Нужен общий
  «последний снимок соединений» (его уже получает опрос раз в 10 с), иначе число адресов будет 0.
- Адреса из списка ядро больше не видит, поэтому их «последний раз» не освежается. Это не ломает:
  через 30 дней адрес забудется, вернётся в туннель и запомнится снова. Записано как известное.
- Перенос привязок (этап 7) — в другой части (серверы) и не зависит от остального. → Отдельно, последним.
  Нынешнюю смену имён он уже не починит: в старом снимке серверов нет адресов.

Новый порядок:
1. Модель: откуда адрес (программа / сайт / вы), наборы сетей Blizzard + Steam, сайты для запоминания,
   отбор адресов с проверкой конфликтов, добавление пачкой. Тесты.
2. Снимок соединений для меню + общий диалог «Добавить / Добавить и применить сейчас».
3. Меню пути: «Через VPN ▸» и действие «Мимо Шлюпки» внизу — сразу во всех местах, где оно есть.
4. Меню соединения («Только IP», «Сайт и поддомены») и «Ошибки».
5. Вкладка: группы, две колонки, новые пункты; метка в «Сейчас в сети».
6. Перенос привязок при смене имён серверов.
7. Все тесты, анализ, снимки экранов.

## Ручные тесты

Проверка пути: `Test-NetConnection <IP> -Port 443` или `Find-NetRoute -RemoteIPAddress <IP>`:
`tun0` / 172.19.0.1 — через Шлюпку, `Ethernet` / 192.168.1.57 — мимо.
