# «Напрямую с обходом» — план (v1, 2026-10-11)

Третий список раздельного туннеля. Сайты из него идут **напрямую, без VPN**, но первый
пакет TLS-соединения (ClientHello с именем сайта) режется на куски так, чтобы фильтр
провайдера не прочитал имя, а сервер собрал запрос как обычно. Это «уровень 1» подхода
zapret: только резка, без поддельных пакетов и без драйвера.

**Зачем.** YouTube и подобное без VPN: полная скорость домашнего канала, домашний IP, VPS
не нагружается.

**Что НЕ решает.**
- Сервисы, которые сами не пускают российские IP (Claude, ChatGPT, Spotify), — только VPN.
- Блокировку по IP-адресу (сервер недоступен целиком) — только VPN.
- UDP: голос Discord, игры, QUIC. Резать можно только TCP.
- Если фильтр провайдера собирает поток целиком, резка не поможет. Проверяется только
  вживую, см. этап 0.

## Что уже есть

| Где | Что |
|---|---|
| ядро, sing-box `route/conn.go` + `common/tlsfragment` | опции действия `route`: `tls_fragment` (режет ClientHello на TCP-куски **посреди каждой части имени сайта** и ждёт подтверждения каждого куска) и `tls_record_fragment` (те же места, но куски — отдельные TLS-записи). Одновременно нельзя. |
| ядро, `v2/config/builder.go` | выход `direct-fragment §hide§`: резка Hiddify, куски случайного размера `fragment_size` с паузой `fragment_sleep`, без учёта места имени. |
| ядро, `v2/config/dns.go` | DNS-сервер `dns-trick-direct`: DoH Cloudflare через `direct-fragment`. |
| ядро, `v2/config/split_tunnel.go` | два локальных набора правил, sing-box перечитывает их сам, порядок «через VPN» → «мимо VPN». |
| приложение, `lib/features/split_tunnel` | модель `SplitTunnel {bypass, via}`, запись наборов в `split/`, экран «Туннель», вкладка «Сейчас в сети». |

## Решения по умолчанию (подтвердить)

1. **Название списка:** «Напрямую с обходом». Короткое имя в таблицах — «Обход».
2. **Порядок:** «через VPN» → «напрямую с обходом» → «мимо VPN» → все остальные правила.
   Если сайт по ошибке попал в два списка, VPN надёжнее, а обход надёжнее прямого.
3. **Способ резки** — настройка, одна на весь список:
   - `split` — `tls_fragment` (по умолчанию, если этап 0 не покажет другое);
   - `record` — `tls_record_fragment`;
   - `chunks` — выход `direct-fragment` с размером и паузой из «Обхода блокировок».
   Смена способа требует переподключения: действие маршрута не перечитывается на лету.
   Сами списки, как и раньше, меняются на лету.
4. **QUIC для сайтов из списка блокируется** (UDP 443 → отказ). Браузер сам переходит на
   TCP, где резка работает. Без этого Chrome уходит в QUIC, и YouTube «то работает, то нет».
5. **DNS сайтов из списка** — как у «мимо VPN» (прямой DNS). Если на этапе 0 окажется, что
   DNS провайдера подменяет ответы, переключить на `dns-trick-direct`.
6. **Готовый набор «YouTube»** — кнопка в пустом списке, по умолчанию список пустой:
   `youtube.com`, `youtu.be`, `youtube-nocookie.com`, `googlevideo.com`, `ytimg.com`,
   `ggpht.com`, `youtubei.googleapis.com`, `youtube.googleapis.com`.
   Discord в набор НЕ входит: текст, может быть, и заработает, а голос (UDP) — нет;
   пусть остаётся через VPN.

## Этап 0. Проверка на живом канале (без изменений кода)

Цель — узнать до программирования, обманывает ли резка фильтр провайдера пользователя и
какой способ лучше. Делаю я, на ПК пользователя. **Шлюпку НЕ выключать**: через неё работает
сам Claude (Anthropic не пускает российские IP). Тестовое ядро обходит туннель Шлюпки так же,
как она сама: все прямые выходы и DNS привязаны к физическому интерфейсу
(`bind_interface: "Ethernet"`). Добавить тестовое ядро в «мимо VPN» нельзя — тогда его
соединения пройдут через стек TUN Шлюпки, тот пересоберёт поток, и резка ClientHello
пропадёт. Контроль: `curl` через тестовый прокси к `api.ipify.org` показывает домашний IP.

1. В scratchpad — конфиг sing-box (HiddifyCli из релиза ядра rb.14): вход `mixed` на
   `127.0.0.1:20808`, четыре правила по входящему порту или по `auth_user`, чтобы в одном
   запуске были четыре варианта:
   прямо без резки / `tls_fragment` / `tls_record_fragment` / `direct-fragment`.
2. Для каждого варианта, по 10 раз: `curl -x socks5h://… -o NUL -w` для
   `https://www.youtube.com/`, `https://i.ytimg.com/`, `https://rr1---sn-….googlevideo.com/`
   (адрес взять из страницы) — успех и время рукопожатия. Фиксировать: отказ, обрыв,
   зависание (типичный признак ТСПУ — соединение висит после ClientHello).
3. Скорость: пользователь открывает видео 1080p в Firefox, настроенном на этот прокси
   (только в Firefox прокси задаётся отдельно от системы), и смотрит «Статистику для сисадминов».
4. Итог — таблица в этом файле: способ → доступность → скорость.
   **Если ни один способ не помог — дальше не идём**, обсуждаем уровень 3 (winws2) или
   оставляем YouTube через VPN.

## Этап 1. Ядро (rb.15)

Файлы в `split-tunnel-dir`, необязательные (нет файла — ядро создаёт пустой, как сейчас):

- `unblock.json` — программы, сайты, IP списка «напрямую с обходом»;
- `unblock-domains.json` — только сайты: для DNS-правила.

Опция `HiddifyOptions.RescueUnblockMode string` (JSON `rescue-unblock-mode`,
`split` | `record` | `chunks`, пусто = `split`).

Изменения в `split_tunnel.go`:

- наборы `rescue-unblock`, `rescue-unblock-domains`;
- маршрут, между «через VPN» и «мимо VPN»:
  1. `rule_set: rescue-unblock` + `network: udp` + `port: 443` → `reject`;
  2. `rule_set: rescue-unblock` → `route` на `direct` с `tls_fragment: true`
     (или `tls_record_fragment: true`; для `chunks` — `route` на `direct-fragment §hide§`
     без опций);
- DNS: `directDNSRule` для `rescue-unblock-domains`, между `via-domains` и `bypass-domains`.

Тесты (`split_tunnel_test.go`): порядок правил, три режима, неизвестный режим → `split`,
пустые файлы создаются, сборка конфига проходит `option.Options` без ошибок
(`tls_fragment` и `tls_record_fragment` вместе sing-box не принимает).

Живая проверка: `HiddifyCli` + `srun` с реальной подпиской, YouTube в списке — `curl`
через вход приложения идёт напрямую (IP домашний), рукопожатие проходит; правка файла
списка на лету применяется.

## Этап 2. Приложение (0.3.0-test1)

Модель (`split_tunnel.dart`):

- `SplitTarget.unblock('Напрямую с обходом')`; `SplitTunnel` получает поле `unblock`.
- `fromJson`: нет ключа `unblock` → пустой список (старый `split-tunnel.json` читается).
- `targetOf` проверяет в порядке via → unblock → bypass, как в ядре.
- `SplitTarget.other` больше не подходит (вариантов три): заменить на явный выбор списка
  в меню «Перенести в…».

Запись (`split_tunnel_notifier.dart`): `unblock.json` и `unblock-domains.json` через тот
же `_writeAtomic`.

Опция ядра: `rescue-unblock-mode` из настроек, по умолчанию `split`.

Экраны:

- «Туннель»: третий список рядом с двумя существующими; в пустом списке — кнопка
  «Добавить YouTube» (набор из п. 6) и строка «что это и что не поможет» (коротко из
  раздела «Что НЕ решает»).
- «Сейчас в сети»: столбец «Путь» показывает «Обход»; в меню строки — «Напрямую с обходом».

- Только по-русски, стиль «Д» (`docs/redesign/style-d.md`).

Тесты: модель (json туда-обратно, старый файл без `unblock`, порядок `targetOf`, набор

## Риски

- Провайдер меняет правила ТСПУ: сегодняшний способ может перестать работать. Ответ —
  выбор способа в настройках и честная подпись; автоподбор — уровень 3, не сейчас.
- `tls_fragment` ждёт подтверждения каждого куска: первое соединение к сайту дольше на
  1–2 RTT. Для видео незаметно, для множества мелких соединений — проверить на этапе 0.
- Антивирусы на резку не реагируют (драйвера нет, это обычные сокеты).
